# آفاق — کالبد Next.js + PostgreSQL (فاز نهایی)

بازسازی فاز صفر (Express/SQLite) روی **Next.js 14 App Router + PostgreSQL + Drizzle ORM** — سه داشبورد ایزوله با نگاشت دادهٔ ۱:۱ و مهاجرت مستقیم SQLite→PostgreSQL.

## راه‌اندازی

```bash
docker compose up -d          # PostgreSQL 16 + MinIO (یا postgres محلی)
cp .env.example .env
npm install
npm run db:push               # ساخت ۷۳ جدول با Drizzle
npm run db:hardening          # ایندکس‌ها + RLS
npm run db:migrate-sqlite     # انتقال دادهٔ فاز صفر (مسیر پیش‌فرض: ../afagh-erp/data/afagh.db)
node scripts/warm-redis.mjs     # §۱۰۰۶: انتقال ظرفیت‌ها به Redis (یا دکمهٔ پنل ادمین)
bash scripts/start-minio.sh &   # §۲۴۴۵: MinIO روی ۹۰۰۰ (کنسول: ۹۰۰۰۱)
npm run dev                   # توسعه (۸۰۸۰)  |  npm run build && npm start
```

## حساب‌های دمو (رمز ۱۲۳۴۵۶)

| نقش | کد ملی | مقصد |
|---|---|---|
| مدیر | 0000000001 | /admin — کارتابل گردش کار + حقوق |
| استاد (رضایی) | 0011111111 | /professor — کلاس‌ها، فیش شفاف، امضای اسناد |

* شماره دانشجویی؛ ورود با کد ملی کاربر دانشجو از `users` (دیتای seed فاز صفر).

## نتایج E2E (پروداکشن build، ۱۴۰۵-۰۶-۰۷)

- ✅ tsc بدون خطا + build موفق (۹ مسیر، middleware ۲۶.۵kB)
- ✅ مهاجرت: **۱۲۳۳ سطر در ۷۳ جدول**؛ سازگاری هش scrypt با فاز صفر تأیید شد
- ✅ ۱۶/۱۶ سناریوی HTTP: ریدایرکت‌ها، ایزولاسیون سه‌گانه (دانشجو↔استاد↔ادمین)، توکن جعلی→login
- ✅ ورود واقعی: Set-Cookie نشست (HttpOnly) + پیام «رمز نادرست است.»
- ✅ چرخهٔ کامل امضا: sendOtp→verify→SIGNED + مهر دیجیتال + `document_signatures` + `audit_logs` زنجیره‌ای؛ شمارش تلاش (۱/۵) کار کرد
- ✅ انتخاب واحد واقعی: add→submit «ساختمان داده، آزمایشگاه فیزیک» REGISTERED، سبد خالی، enrolledCount، اعلان ENROLLMENT_DONE — سپس rollback کامل دیتای تست

## اتاق انتظار Redis — نتایج E2E (۷ اجرا، دیتای تست کاملاً rollback شد)

- ✅ گرم‌کردن: ۱۴ کلاس ترم جاری از PG به `afagh:caps` (دکمهٔ پنل ادمین + اسکریپت cron)
- ✅ **چک اتمیک §۱۰۱۴**: ۳۵ درخواست همزمان روی ظرفیت ۳۰ → دقیقاً ۳۰ قبول / ۵ رد (Lua، بدون overbooking)
- ✅ **صف §۱۰۱۶**: ثبت نهایی → پاسخ فوری `queued:true` + نوبت؛ نظرسنجی: نوبت ۵۱ → ۴۶ → … → ۱ → DONE با نتیجه؛ فقط نتیجهٔ نهایی به PostgreSQL می‌رسد (§۶۹۰۶)
- ✅ **ارتقای خودکار §۱۰۱۸–۱۰۲۶**: مریم WAITLISTED ردیف ۱ → حذف علی → بلافاصله REGISTERED + اعلان «WAITLIST_PROMOTED: ساختمان داده» — enrolledCount به ۱ برگشت، نه ۰!
- ✅ **سپر نرخ §۲۰۷۷**: ۷ ثبت پشت‌سرهم → پنج اول مجاز، شش‌م و هفتم `limited`
- ✅ تداوم سرویس: Redis قطع → موتور خودکار به شمارش SQL برمی‌گردد؛ upsert مقاوم به re-register پس از حذف (`uq_enrollments`)
- ✅ ظرفیت زنده در UI از `/api/enroll/live-capacity` (§۳۴۰۳) — دیتابیس در گیر نمی‌شود

## فیلتر پیش‌نیاز — نتایج E2E (وفادار کلمه‌به‌کلمه به `engines/enrollment.js` فاز صفر)

- ✅ **عدم پیش‌نیاز (خطای نرم)**: پایگاه داده بدون گذرانده‌شدن ساختمان داده → «عدم پیش‌نیاز: «پایگاه داده» نیازمند گذرانده‌شدن «ساختمان داده» است.» — ثبت نشد، سبد حفظ شد
- ✅ **درخت OR**: معماری کامپیوتر = (برنامه‌نویسی پیشرفته **یا** مفاهیم ابتدایی ریاضیات) — برچسب UI درست رندر شد
- ✅ **نمرهٔ قبولی مؤثر**: اورراید `course_rules.customPassingGrade` > `degree_level_configs.defaultPassingGrade` (توصیفی = ۱) — ساختمان داده با قاعدهٔ سیلابسی (حداقل ۱۲) برای دانشجوی منطبق اعمال می‌شود
- ✅ **تداخل امتحانی (خطای نرم، بازگردانده‌شده از فاز صفر)**: ساختمان داده (امتحان ۱۴۰۵/۱۱/۰۴ ۱۰:۰۰) با برنامهٔ موجود → «تداخل امتحانی … (2026-12-25)»
- ✅ **مثبت**: زبان انگلیسی ۱ (بدون پیش‌نیاز/تداخل) → REGISTERED
- ✅ **ارجاع به کمیسیون**: ثبت PENDING_COUNCIL + پروندهٔ گردش کار `PREREQ_WAIVER` با کد رهگیری WR-…، گام اول، اتصال دوطرفهٔ `enrollments.workflowRequestId` — و نمایش فوری در کارتابل ادمین
- ✅ **فیلتر ۲ب (بازگردانده‌شده)**: تکرار همان درس در گروه دیگرِ همان ترم = خطای سخت

## نوشتن تحت RLS + WebUI بایگانی — نتایج E2E

- ✅ **سیاست‌های نوشتن (۱۱ سیاست/۴ جدول)**: سبد دیگران ⛔ RLS violation؛ اعلان برای دیگری ⛔؛ حذف سبد دیگران → ۰ ردیف؛ نوشتن برای خود ✓
- ✅ **باگ واقعی گرفته‌شد**: `ENABLE ROW LEVEL SECURITY` روی ۳ جدول فراموش شده بود (سیاست‌ها بی‌اثر) — فعال‌سازی idempotent هر ۴ جدول + گرانت sequence ها
- ✅ **جریان کامل اپ زیر RLS**: افزودن سبد → ثبت از صف (درج enrollments + خالی‌کردن سبد + اعلان) → حذف درس (DROPPED + شمارنده توسط نقش مالک) — همهٔ نوشتن‌های دانشجو با `withUserRls`
- ✅ **پنل بایگانی**: `/admin/archive` جدول+آپلود+تأیید/رد با دلیل (prompt) + ممیزی `ARCHIVE_DOC_VERIFIED/REJECTED`؛ `/student/documents` مدارک خود دانشجو با مشاهدهٔ امضاشده
- ✅ **سلف-آپلود e-KYC**: دانشجو برای خودش ✓ / برای دیگری 403

## RLS و Object Storage — نتایج E2E

- ✅ **RLS در سطح دیتابیس**: نقش `afagh_app` بدون uid → **صفر ردیف**؛ uid=11 → ۶ ثبت‌نام علی؛ uid=12 → ۷ ثبت‌نام مریم — جدایی کامل بدون اتکا به کد اپ
- ✅ **wiring اپ**: کارنامهٔ دانشجو از استخر `afagh_app` با `set_config('app.user_id', …, true)` محلیِ تراکنش خوانده می‌شود — ردیف دیگران در سطح DB «ناموجود» است، حتی با بایپس کامل کد
- ✅ **MinIO**: بارگذاری مدرک (۴۴ بایت) → شیء `archive/11/…` در باکت + ردیف DB فقط URL/هش + رویداد زنجیره‌ای `ARCHIVE_FILE_STORED` (prev → هش قبلی زنجیره)
- ✅ **سرو امضاشده**: مالک → 307 به URL امضاشدهٔ AWS4 (۵ دقیقه) → محتوا مستقیم از MinIO؛ سند دیگران → 403؛ بدون نشست → 401
