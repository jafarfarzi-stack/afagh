# سامانه جامع آموزشی دانشگاه آفاق

پروژهٔ کامل یک سیستم دانشگاهی مدرن در دو نسل — هر دو از یک طراحی واحد (سند اصلی) پیاده‌سازی شده‌اند و E2E تست‌اند:

| | مسیر | پشته | توضیح |
|---|---|---|---|
| **کالبد مدرن** | [`afagh-next/`](afagh-next/README.md) | Next.js 14 + PostgreSQL + Drizzle + Redis + MinIO | سه داشبورد ایزوله، امضای الکترونیک، اتاق انتظار Redis، RLS کامل، Object Storage |
| **فاز صفر** | [`afagh-erp/`](afagh-erp/README.md) | Node خالص + SQLite (بدون وابستگی سنگین) | ۱۲ ماژول کامل آموزشی/مالی/اداری + تست بار ۲۰۰۰ کاربر |

## شروع سریع

```bash
./install.sh    # نقش‌ها + ۷۳ جدول + RLS + دادهٔ دمو + Redis + بیلد
./start.sh      # کالبد روی :8080  (دموی فاز صفر: ./start.sh --with-demo)
```

**استقرار پروداکشن با Docker (پیشنهادی):**

```bash
docker compose up -d --build     # یا: make up   → http://SERVER_IP:8080
make up-https                    # اختیاری: پشت Caddy با HTTPS خودکار (DOMAIN در .env)
sudo ./deploy-debian.sh          # سرور تازهٔ Debian 13: نصب داکر + رمزهای تصادفی + استقرار
```

**نصب توسعه با Docker (ویندوز / لینوکس / مک):**

```powershell
powershell -ExecutionPolicy Bypass -File .\install-docker.ps1 -WithDemoData   # ویندوز
./install-docker.sh --with-demo-data                                          # لینوکس/مک
```

جزئیات کامل: [`INSTALL.md`](INSTALL.md)

## انتقال داده از سرورهای قدیمی

پنل مدیر ← **🔄 انتقال داده از سیستم قدیمی** (`/admin/migration`) — چهار میز کار در یک صفحه:

| میز | کار |
|---|---|
| **دادهٔ پایه** | دانشجو، درس، ترم، ثبت‌نام، صورت‌حساب و تسویه — با «تحلیل اولیه» قبل از «ثبت نهایی» |
| **تطبیق کدها** | کد رشته/مقطع/ترم/درس/وضعیت سیستم قدیمی → موجودیت سامانهٔ جدید، با پیشنهاد خودکار |
| **شهریه و مالی** | انتقال فرمول‌های شهریه، ارزیابی امن آن‌ها و **مقایسه با شهریهٔ واقعی سیستم قدیمی** |
| **نمرات** | واردسازی در جدول موقت، مقایسه با نمرات فعلی سامانه، اعمال کنترل‌شده (نمرهٔ کیفی هم پشتیبانی می‌شود) |
| **ناحیهٔ موقت و واگرد** | سطرهای خام هر فایل، پردازش دوبارهٔ خطادارها بدون آپلود مجدد، و **واگرد کامل هر دسته/عملیات** |

ورودی همه‌جا **اکسل (`.xlsx`)** یا CSV است، برای هر بخش **قالب اکسل** دانلود می‌شود و همهٔ گزارش‌ها
خروجی اکسل دارند. پیش از واردسازی می‌توانید با **«بررسی ستون‌ها»** نگاشت ستون‌های فایل را ببینید و
اصلاح کنید، و بعد از واردسازی هر عملیاتی **برگشت‌پذیر** است.
راهنمای کامل: [`docs/MIGRATION.md`](docs/MIGRATION.md)

## 📐 موتور آیین‌نامه‌های آموزشی

سقف واحد مجاز، مشروطی، سنوات، معدل رسمی و ارجاع خودکار به کمیسیون موارد خاص از روی
آیین‌نامهٔ مصوبِ همان دانشجو محاسبه می‌شود. مسدودسازی دانشجو و ساخت پروندهٔ کمیسیون در
یک **تراکنش اتمی** انجام می‌شوند (خطا ⇒ Rollback کامل)، محاسبات معدل روی **اعداد صحیح**
انجام می‌شود تا خطای ممیز شناور رخ ندهد، و نمرهٔ خالی/نامعتبر هرگز صفر حساب نمی‌شود.
راهنما: [`docs/REGULATIONS.md`](docs/REGULATIONS.md)

موتور گردش کار (BPM) با تراکنش‌های اتمی، گذرگاه رویداد و موتور حق‌التدریس:
[`docs/WORKFLOW.md`](docs/WORKFLOW.md) · [`docs/PAYROLL.md`](docs/PAYROLL.md)

گزارش‌های هوش تجاری ارزشیابی (داشبورد گلوگاه کیفی، تحلیل امکانات کلاس‌ها و ابر
کلمات نظرات) با **کوئری‌های تجمیعی** و **تحلیل متن در خود PostgreSQL** ساخته
می‌شوند — بدون N+1 و بدون بلاک‌شدن سرور وب — و نتیجه در جدول کش می‌نشیند:
[`docs/BI.md`](docs/BI.md)

## 🎓 فارغ‌التحصیلی، تسویه‌حساب و پورتال دانش‌آموختگان

فرآیند **رویدادمحور** است: دانشجو هیچ درخواستی ثبت نمی‌کند. با قطعی‌شدن آخرین نمره،
سامانه کارنامه را با سرفصل تطبیق می‌دهد، پرونده را باز می‌کند و به کارتابل مدیر گروه
می‌فرستد؛ سپس همانندجویی ایرانداک — فقط برای مقاطع دارای پایان‌نامه (ارشد/دکتری) — خودکار
استعلام و تسویه‌حساب **همهٔ دپارتمان‌ها هم‌زمان** آغاز می‌شود. هر واحدی که سیستم بتواند خودش بسنجد (مثلاً بدهی مالی)
بدون دخالت کارشناس سبز می‌شود. دانشجو فقط یک **نوار پیشرفت** می‌بیند
(`/student/graduation`) و تنها دو اقدام از او خواسته می‌شود: پس از کامل‌شدن همهٔ امضاها
باید خودش در **سامانهٔ سجاد** درخواست «کد صحت» ثبت کند و کد رهگیری‌اش را وارد نماید — تا آن
زمان پرونده به کارشناس صدور مدرک نمی‌رسد — و در پایان عکس ۴×۳ و تمبر ابطال.

سپس گواهینامهٔ موقت با QR و امضای SHA-256 صادر می‌شود، دانشنامهٔ اصلی پس از دریافت
**کد صحت** وزارت علوم (سجاد)، و حساب کاربر به **پورتال دانش‌آموختگان** (`/alumni`) منتقل
می‌شود؛ آنجا ریزنمرات رسمی، تأییدیه برای دارالترجمه و آزادسازی مدرک به‌صورت آنلاین و
پولی قابل درخواست است. استعلام عمومی اصالت مدرک: `/verify-degree/<کد>`.
میز کار اداره آموزش: `/admin/graduation` — راهنمای کامل: [`docs/GRADUATION.md`](docs/GRADUATION.md)

**اطلاع‌رسانی چندکاناله:** همان لحظه‌ای که پرونده باز می‌شود، پیام **تبریک اتمام تحصیل به
همراه دعوت به پیگیری تسویه‌حساب** برای دانشجو ارسال می‌شود و بقیهٔ مراحل هم به‌صورت
لحظه‌ای اطلاع داده می‌شوند — نه فقط داخل سامانه، بلکه با **پیامک** یا **پیام‌رسان**
(تلگرام/بله/ایتا). سرویس‌دهنده، کلیدها، نشانی API و فهرست کانال‌های فعال کاملاً از
«تنظیمات ← پیامک و ربات‌های پیام‌رسان» قابل تغییرند (`NOTIFY_CHANNELS`, `SMS_PROVIDER`,
`SMS_BASE_URL`, …) و نتیجهٔ هر ارسال در گزارش تحویل ثبت و به کارشناس نشان داده می‌شود.

## حساب‌های دمو (رمز همه `123456`)

| نقش | کد ملی | مقصد |
|---|---|---|
| مدیر | 0000000001 | `/admin` — کارتابل + حقوق + بایگانی |
| استاد | 0011111111 | `/professor` — کلاس‌ها + امضای الکترونیک |
| دانشجو | 31412001 | `/student` — کارنامه + انتخاب واحد |

## قابلیت‌های شاخص

- **انتخاب واحد مقاوم در برابر هجوم**: ظرفیت اتمیک در Redis (Lua)، صف FIFO با نوبت زنده، ارتقای خودکار لیست انتظار، سپر نرخ
- **خط لولهٔ ۵ فیلتری**: مالی → ظرفیت → سقف واحد → پیش‌نیاز (درخت AND/OR) → تداخل کلاس/امتحان؛ خطای نرم = ارجاع به شورا با گردش کار
- **امنیت دفاع-عمقی**: RBAC + ممیزی زنجیره‌ای SHA-256 + **RLS سطح دیتابیس** (خواندن و نوشتن)
- **بایگانی الکترونیک**: فایل‌ها در MinIO (S3)، لینک امضاشدهٔ موقت، e-KYC
