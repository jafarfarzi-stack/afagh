# مرحلهٔ دوم تثبیت — یکپارچه‌سازی حسابرسی

## نتیجه
تمام درج‌های مستقیم Drizzle در audit_logs در کد src به یک نویسنده منتقل شدند: audit-writer.ts. فراخواننده‌های appendAudit و auditChain سازگار باقی ماندند؛ مسیرهای مستقل حقوق و امضای استاد نیز به آن متصل شدند. بایگانی از مرحلهٔ اول از appendAudit استفاده می‌کند.

## طراحی
- قفل تراکنشی مشترک PostgreSQL با pg_advisory_xact_lock پیش از خواندن سر زنجیره؛ قفل حتی برای جدول خالی کار می‌کند.
- تنها READ COMMITTED پذیرفته می‌شود تا SELECT پس از گرفتن قفل، سر تازه را ببیند؛ isolationهای دیگر صریحاً رد می‌شوند.
- قالب v2 در details با envelope دارای auditFormat و data مشخص می‌شود. data همان رشتهٔ جزئیات ورودی یا null است.
- هش از ترتیب ثابت فیلدهای ذخیره‌شده ساخته می‌شود: نسخه، کاربر، عملیات، نوع/شناسهٔ موجودیت، details، IP، زمان ذخیره‌شده و prevHash.
- createdAt به‌صورت صریح ذخیره می‌شود؛ زمان ناپایدار یا ذخیره‌نشده وارد هش نمی‌شود.
- سوابق قدیمی تغییر نمی‌کنند. ابزار راستی‌آزمایی هش آن‌ها را تأییدنشده گزارش می‌کند؛ پیوندهایشان بررسی می‌شود. پس از شروع v2 بازگشت به قالب قدیمی خطاست.
- ابزار AST برای جلوگیری از برگشت درج مستقیم Drizzle خارج از نویسندهٔ مشترک به npm test اضافه شد؛ این ابزار تحلیل امنیتی جامع یا parser SQL نیست.
- اسکریپت تست بار امتحانات برای استفاده از verifier مشترک به‌روز شد؛ خود تست بار امتحانات در این مرحله اجرا نشد.

## تست‌های اجراشده
- PostgreSQL 17.11 محلی، جدول‌های آزمایشی در schema تصادفی و مستقل؛ پس از تست schema پاک شد.
- ۶۰ تراکنش هم‌زمان و ۷۲ رکورد با هش قابل‌بازمحاسبه و زنجیرهٔ سالم، از جدول خالی.
- rollback تغییر کاری و لاگ پس از خطای عمدی.
- rollback تغییر کاری هنگام شکست درج حسابرسی.
- رد repeatable read و آزادشدن قفل بعد از خطا؛ درج بعدی موفق.
- ۴ تست واحد جدید: بازتولید هش، دست‌کاری فیلدها، شکست پیوند/حذف میانی/تکرار/افت نسخه، تفکیک سابقهٔ قدیمی.
- npm test: ۴۴۶ بررسی اولیه + ۵ تست بایگانی + ۴ تست حسابرسی موفق؛ کنترل نویسنده نیز موفق.
- npm run typecheck، npm run build و git diff --check موفق.
- تست یکپارچه به job دارای PostgreSQL در CI اضافه شد؛ اجرای GitHub Actions هنوز تأیید نشده است.

## اجرای مجدد
از afagh-next:

```bash
npm test
npm run typecheck
AUDIT_TEST_DATABASE_URL='postgres://...' npm run test:audit-integration
AUDIT_DATABASE_URL='postgres://...' npm run audit:verify
```

تست یکپارچه فقط برای دیتابیس آزمایشی است؛ schema اختصاصی ایجاد و حذف می‌کند. راستی‌آزمایی فقط SELECT می‌زند؛ حساب فقط‌خواندنی توصیه می‌شود. verifier فعلی کل لاگ‌ها را در حافظه می‌خواند؛ برای حجم بسیار زیاد باید cursor/snapshot اضافه شود.

## محدودیت‌ها و نکات استقرار
- قفل advisory همکاری همهٔ نویسنده‌ها را لازم دارد. SQL دستی، اسکریپت قدیمی یا سرویس خارجی که قرارداد را رعایت نکند می‌تواند زنجیره را خراب کند.
- برای استقرار، نوشتن‌های نسخهٔ قدیمی متوقف و تراکنش‌های درحال اجرا تمام شوند؛ rolling deployment هم‌زمان با نویسندهٔ قدیمی امن نیست.
- مصرف‌کننده‌های خارجی details باید envelope جدید را بشناسند. مهاجرت اسکیما لازم نیست، ولی قرارداد داده تغییر کرده است.
- زنجیرهٔ هش امضای دیجیتال یا ذخیره‌ساز غیرقابل‌تغییر نیست. مدیر دیتابیس می‌تواند همهٔ زنجیره را بازنویسی کند؛ کشف آن یا حذف انتهای زنجیره نیازمند checkpoint مستقل و کنترل دسترسی/نگهداری بیرونی است.
- مسئلهٔ هم‌زمانی فرایند OTP امضای استاد خارج از این بسته است؛ این مرحله فقط نویسندهٔ حسابرسی آن را اصلاح کرد.
- سرور کامل، RLS، MinIO و بار فرایندهای واقعی هنوز در این مرحله آزمایش نشده‌اند.
- تغییرات محلی‌اند؛ push یا استقرار صورت نگرفته است.
