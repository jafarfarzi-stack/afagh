# مرحلهٔ سوم محدود — اعتماد پروکسی

به درخواست کاربر این بسته فقط مرز اعتماد را اصلاح می‌کند؛ INCR/EXPIRE، الگوریتم سهمیه و fallback حافظهٔ Rate Limit تغییر نکرده‌اند.

## تغییرات
- helper مشترک IP با اعتماد خاموش پیش‌فرض، راز مشترک، هدر اختصاصی و اعتبارسنجی/نرمال‌سازی IP.
- حذف خواندن مستقیم هدرهای forwarded از مسیرهای Rate Limit، استعلام قدیمی، امضای استاد، قرارداد، حسابرسی و احراز هویت.
- Secure کوکی براساس تنظیمات استقرار، نه Host یا هدرهای درخواست.
- بازنویسی IP و توکن در Caddy و حذف هدرهای قدیمی مرتبط.
- حذف پورت منتشرشدهٔ اپ در Compose HTTPS با !reset، مستقل از APP_PORT.
- افزودن متغیرهای محیطی و راهنمای فعال‌سازی در docs/PROXY_TRUST.md.

## اعتبارسنجی
- تمام تست‌های npm test موفق: ۴۴۶ بررسی اولیه + ۵ تست بایگانی + ۴ تست حسابرسی + ۴ تست جدید پروکسی، همراه کنترل نویسندهٔ لاگ.
- تایپ‌چک و بیلد موفق.
- Caddy 2.6.2: validate پیکربندی موفق؛ درخواست واقعی با X-Forwarded-For/X-Real-IP/IP اختصاصی/توکن جعلی از پروکسی عبور کرد و IP واقعی اتصال برگشت؛ مسیر مستقیم جعلی نامطمئن بود.
- Docker Compose 2.26.1: ترکیب واقعی فایل‌های پایه و HTTPS بررسی شد؛ با APP_PORT=8080 هیچ port mapping برای اپ باقی نماند؛ راز مشترک و فلگ‌ها مطابق انتظار بودند.
- اسکن src: هیچ خواندن مستقیم get('x-forwarded…') یا get('x-real-ip') باقی نماند.
- git diff --check موفق.

## اجرا نشده / محدودیت‌ها
- گواهی TLS، تست مرورگری کوکی و استقرار کامل کانتینرها اجرا نشده‌اند.
- تست یکپارچه از Caddy واقعی و backend کوچک با helper واقعی اپ استفاده می‌کند، نه کل Next و دیتابیس.
- اجرای مستقیم بدون پروکسی امن سهمیهٔ IP مشترک unknown دارد؛ این رفتار باید در استقرار در نظر گرفته شود.
- CDN/پروکسی چندمرحله‌ای، CSRF و سیاست منشأ، و اصلاح شمارندهٔ Redis خارج از این بسته‌اند.
- راز صرفاً باید در محیط خصوصی نگهداری شود؛ نفوذ به سرویس/شبکهٔ مورداعتماد همچنان یک ریسک است.
- هیچ push یا استقرار صورت نگرفته؛ تمام تغییرات محلی‌اند.
