# مرحلهٔ اول تثبیت — امنیت بایگانی

مبنا: 6840802. تغییرات محلی‌اند؛ هیچ push یا استقرار انجام نشده است.

## تغییرات
- اعتبارسنجی کلید ذخیره‌سازی پیش از خواندن محلی یا S3؛ رد مسیر مطلق، traversal، backslash و NUL.
- بررسی realpath و محدودهٔ پوشه برای جلوگیری از خروج از uploads با symlink؛ خواندن غیرهمگام و محدودیت ۱۰ مگابایت برای فایل محلی و جریان S3.
- حذف کامل SVG جایگزین سند؛ نبود کلید واقعی 404، خرابی ذخیره‌ساز 503، حجم غیرمجاز 413.
- خطاهای دریافت بدون افشای پیام داخلی و با no-store برمی‌گردند.
- اعتبارسنجی شناسه و تصمیم؛ تصمیم خالی یا ناشناخته دیگر VERIFIED نیست.
- درج مدرک و حسابرسی، و همچنین تغییر وضعیت و حسابرسی، در تراکنش مشترک PostgreSQL.
- بررسی نوع ورودی فایل و اندازهٔ اعلام‌شده پیش از arrayBuffer؛ ذخیرهٔ SHA-256 کامل در جزئیات حسابرسی.
- پنج تست جدید با چندین ورودی منفی در دستور npm test ادغام شدند.

## اعتبارسنجی اجراشده
- npm run typecheck: موفق
- npm test: ۴۴۶ بررسی پیشین و ۵ تست جدید موفق
- npm run build: موفق (پس از آخرین اصلاحات آپلود)
- git diff --check: موفق

## محدودیت‌ها و ادامه
- تست HTTP با نشست واقعی، تست قطع MinIO و اثبات rollback با دیتابیس واقعی هنوز اجرا نشده‌اند؛ تست‌های جدید helperهای واقعی را اجرا می‌کنند، نه سرور کامل را.
- appendAudit فعلی هنوز رقابت هم‌زمانی دارد؛ انتقال بایگانی به این تابع به معنی رفع آن نیست. بستهٔ بعدی: یکپارچه‌سازی تمام نویسندگان audit، قفل تراکنشی مشترک، قالب هش نسخه‌دار و تست هم‌زمانی.
- تراکنش PostgreSQL شامل MinIO نیست؛ شکست DB بعد از آپلود می‌تواند شیء یتیم بگذارد. پاک‌سازی باید با reconciliation انجام شود، نه حذف بی‌قید پس از خطای مبهم commit.
- parser فرم کل درخواست را پیش از بررسی file.size دریافت می‌کند؛ برای دفاع در برابر درخواست بسیار بزرگ، محدودیت بدنه در پروکسی نیز لازم است.
- اعتبارسنجی magic bytes/اسکن بدافزار هنوز انجام نشده است.
- پوشه‌های آپلود نباید توسط کاربران نامطمئن سیستم‌عامل قابل تغییر باشند؛ realpath و O_NOFOLLOW جای جداسازی مجوز سیستم‌عامل را نمی‌گیرند.
- مراحل بعد از حسابرسی: مرز اعتماد پروکسی، rate limit، ممیزی مجوزها، سپس تست یکپارچه و بازیابی پشتیبان.
