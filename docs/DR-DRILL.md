# تمرین بازیابی پشتیبان (DR Drill) — آفاق ERP

## هدف
اثبات اینکه پشتیبان‌های گرفته‌شده **قابل بازگردانی** هستند و پس از بازگردانی RLS و دادهٔ حساس دست‌نخورده می‌مانند.

## RPO / RTO
- **RPO (نقطهٔ بازیابی):** ≤ ۲۴ ساعت (پشتیبان روزانهٔ خودکار توسط migrator + پشتیبان دستی قبل از هر استقرار).
- **RTO (زمان بازگردانی):** ≤ ۲ ساعت برای بازگردانی کامل پایگاه داده + سرویس.

## دورهٔ تمرین
- **سه‌ماهه** (فصلی) — حداقل یک بار در هر فصل.
- پس از هر تغییر عمدهٔ اسکیما (مهاجرت Drizzle) یک تمرین اضافی.

## پیش‌نیازها
- `pg_dump` / `pg_restore` / `psql` روی سرور.
- کلید رمزنگاری (`AFAGH_BACKUP_ENC_KEY` یا `AGE_RECIPIENT`) در یک گاوصندوق (vault) جدا از سرور.
- یک کپی off-host از پشتیبان (S3/MinIO دیگر یا NAS) — هرگز فقط روی همان سرور.

## مراحل تمرین (Quarterly)
1. **انتخاب پشتیبان:** آخرین `afagh-*.dump.enc` (یا `.dump`).
2. **انتقال off-host → سرور تمرین** (یا همان سرور در دیتابیس scratch).
3. **اجرای restore-drill:**
   ```bash
   DATABASE_URL=postgres://.../afagh_prod \
   AFAGH_BACKUP_ENC_KEY=... \
   scripts/phase5/restore-drill.sh /path/to/afagh-YYYY-MM-DD.dump.enc
   ```
4. **بررسی یکپارچگی:**
   - شمار ردیف جدول‌های کلیدی (`users`, `students`, `staff`, `enrollments`, `financial_records`) با مبدأ برابر باشد.
   - RLS روی جدول‌های حساس فعال باشد.
   - یک نمونهٔ کاربری واقعی بتواند وارد شود و دادهٔ خود را ببیند.
5. **بازیابی سرویس:** تصویر قبلی + پایگاه بازگردانی‌شده → `docker compose up -d` → smoke test.
6. ** evidence:** ذخیرهٔ گزارش (تاریخ، نام پشتیبان، شمار ردیف‌ها، زمان بازگردانی، نتیجه) در `docs/dr-drill-evidence/`.

## شکست تمرین
- اگر بازگردانی شکست خورد یا RLS فعال نشد → **حادثهٔ امنیتی** تلقی کنید.
- پشتیبان‌گیری و فرآیند restore را بلافاصله بازبینی کنید.
- تا رفع، هر استقرار را متوقف کنید.

## نکات امنیتی
- کلید رمزنگاری پشتیبان را در همان سرور ذخیره نکنید.
- دیتابیس scratch را همیشه پس از تمرین حذف کنید (اسکریپت این کار را می‌کند).
- هرگز `restore-drill.sh` را با نام پروداکشن به‌عنوان scratch اجرا نکنید — اسکریپت این حالت را رد می‌کند.
- پشتیبان رمزنشده را در مخزن گیت قرار ندهید.
